# Stable Frame

## 日志约定

`PipelineContext.wait_for_stable_frame()` 以 `INFO` 记录等待开始、相机名、超时和成功
返回的稳定帧号；稳定帧在返回前被缓存淘汰或等待超时时记录 `WARNING`。逐帧差分与
窗口内部状态不逐帧写日志，避免相机常驻运行时产生高频日志。

## 单一职责

`stable_frame` 按时间顺序接收相机帧，判断连续画面是否稳定；达到稳定时长后，只输出稳定窗口时间中点附近的 `frame_id`。RGBD 模式同时检查彩色和深度，纯彩色模式只检查时间连续性和 RGB 变化。

它不连接相机、不等待或缓存原始帧、不执行网络传输、不调用其他算法，也不保证目标帧仍位于外部缓存中。帧循环和目标帧回取由 `PipelineContext` 负责。

## 模块结构

- `types.py`
  - `StableFrameConfig`：时间、RGB 和深度阈值。
- `detector.py`
  - `StableFrameDetector`：短时特征历史和稳定状态判定。
- `__init__.py`：导出公共算法类型。

输入帧依赖顶层协议：

- `update()` 接收 `StableRgbdFrameProtocol`，要求帧号、时间戳、彩色图和深度图；
- `update_color()` 接收 `StableColorFrameProtocol`，不读取或要求深度图。

两种入口都不依赖相机运行时的具体 packet、相机名或内参。

## 输入输出

输入帧字段：

- `frame_id: int`；
- `timestamp_ms: float`，必须严格递增；
- `color_bgr: uint8 (H, W, 3)`；
- `depth_mm: uint16 (H, W)`，`0` 表示无效。

未达到稳定时间返回 `None`；达到后返回中点帧号。例如 `stable_duration_s=1.0` 时，选择最接近 `t0+0.5s` 的帧，等距时选择较早帧。

## 成功与失败语义

- 稳定窗口尚未形成：`update()` 返回 `None`，表示继续收帧，不是异常。
- 稳定窗口形成：返回中点附近的正数 `frame_id`。
- 时间戳倒退、帧间隔过大或稳定指标超阈值：重置窗口并返回 `None`。
- 输入数组或时间戳不符合协议：抛出异常，由 `PipelineContext` 转换为请求错误。
- 稳定帧已产生但缓存无法回取：属于业务层帧生命周期错误，不返回伪造帧。

## 算法理论

图像先按 `image_scale` 缩小。相邻灰度帧之差减去其中位数，以抑制全局曝光偏移；随后计算：

- 平均绝对灰度差；
- 超过像素变化阈值的像素比例。

深度仅比较两帧共同有效区域，计算：

- 共同有效像素比例；
- 深度绝对差中位数；
- 深度绝对差高分位数。

不同安装位的深度噪声基线明显不同，不再共用一组深度阈值。2026-07-29
在 Orin 上重新采集三台静止相机的相邻帧指标，得到实测范围：

| 安装位 | 深度差中位数 | 深度差 75 分位 | 配置中位阈值 | 配置 75 分位阈值 |
| --- | ---: | ---: | ---: | ---: |
| 头部 | `14-15 mm` | `33-34 mm` | `18 mm` | `45 mm` |
| 胸腔 | `4 mm` | `24-25 mm` | `6 mm` | `35 mm` |
| 左臂 | `29-30 mm` | `120-124 mm` | `40 mm` | `160 mm` |

分相机阈值由 `PipelineContext` 的安装位端点配置持有。三路仍共用彩色变化、
有效深度比例、帧连续性和 `1 s` 连续稳定时长约束，不是仅凭放宽深度阈值直接判定稳定。

头部相机旧基线为中位差 `6-7 mm`、75 分位差 `18 mm`。2026-07-29 现场流已
整体上升到中位差 `14-15 mm`、75 分位差 `33-34 mm`，旧阈值会让全部静止相邻
帧失败，因此按新静止基线保留余量更新，不改变 RGB 和时间约束。

RGBD 入口要求 RGB 和深度指标同时满足阈值；纯彩色入口完全跳过深度特征提取和
深度阈值。两种入口遇到时间戳倒退、相邻帧间隔过大或其启用指标超限时都会重置
稳定区间。

## 调参建议

1. 分别采集完全静止、停止后振动、目标运动、曝光变化和深度空洞片段。
2. 先确定 `max_frame_gap_ms` 能覆盖正常帧间隔但能识别断流。
3. 根据静止噪声分布设置 RGB 平均差和变化比例阈值。
4. `color_pixel_delta_threshold` 应高于传感噪声，低于真实边缘运动变化。
5. 深度中位数阈值反映全局稳定，高分位阈值约束较大范围运动；分位数不能高到由静止边缘飞点主导。
6. `min_valid_depth_ratio` 应排除大面积无效深度场景。
7. 最后根据机械残余振动调整 `stable_duration_s`，不能用缩短时间掩盖阈值错误。

## 局限性

- 判断的是画面稳定，不等价于机器人控制器已经停止。
- 无法从视觉上严格区分相机运动和场景目标运动。
- 全局亮度中位数补偿不能处理局部光照闪烁。
- 很小的局部运动可能低于变化比例阈值。
- 默认阈值是第一版工程参数，必须使用真实相机重新标定。
- 中点帧能否回取取决于 `CameraStreamRuntime` 缓存容量。

## Debug

当前模块不生成 debug 图像或文件。若后续需要暴露指标，应通过显式协议结果返回，并允许关闭；算法内部不得写文件。
