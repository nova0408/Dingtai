# CameraPipeline 版本日志

当前版本：`1.11.0`

## 版本号规则

版本号使用 `a.b.c`：

- `a`：重大重构或重大更新。
- `b`：功能调整，包括新增、删除或改变 API、协议能力及服务行为。
- `c`：缺陷修复和不改变功能边界的优化。

每次更新 API 或功能时，必须同步更新当前版本号，并在本文件顶部追加带日期的版本记录。同一批改动只升级一次，按影响最大的改动选择版本位。

## 1.11.0 - 2026-08-10

### 新增

- ChArUco 检测支持当前 OpenCV `cv2.aruco` 暴露的全部预定义字典，不再固定为单一 AprilTag 字典。

## 1.10.1 - 2026-08-07

### 修复

- 恢复 `camera_stream.runtime` 的 ZMQ 相机流职责，移除服务启动导入链中的
  `pyorbbecsdk`、Open3D 和 Orbbec 实验代码依赖。
- 保留 Orbbec USB 依赖在 `pipeline_context` 的 USB 分支按需导入；三球实验继续位于
  `experiments/`，不再覆盖 `CameraStreamRuntime` 公共导出。

## 1.10.0 - 2026-07-31

### 新增

- 增加 `GET /api/v1/cameras` 相机清单接口，仅返回已配置、已连接且已有最新帧的相机。
- GUI 改为消费 HTTP 相机清单，不再遍历固定相机枚举，也不再为未连接相机发起状态请求。

## 1.9.1 - 2026-07-31

### 变更

- 统一对外 HTTP URL 使用小写资源名和短横线命名：检测路径改为 `/api/v1/detections/ball`
  与 `/api/v1/detections/charuco`，相机路径参数改为 `{camera}`。
- OpenAPI `operationId`、AsyncAPI channel 和 operation 标识统一改为 `snake_case`；内部
  ZMQ `CPW1`、`PROTOCOL_VERSION=10` 和 JSON body 字段保持不变。
- 增加 `service/http_client.py`，将 HTTP/JSON 和 `CPWS1` WebSocket 解析封装为可复用的
  `CameraPipelineHttpClient`，GUI 和其它项目不再需要直接依赖内部 ZMQ client。

## 1.9.0 - 2026-07-31

### 新增

- 增加对外 HTTP/JSON 控制适配层，提供健康检查、相机状态、内参、稳定帧、三球检测和
  ChArUco 检测接口；内部 ZMQ RPC 和算法编排保持不变。
- 增加标准库实现的 WebSocket 最新帧订阅层，使用 `CPWS1` 二进制帧协议提供 color、depth
  和 rgbd 三种流；每个连接只发送最新帧，不建立无界积压队列。
- 增加 `API Reference.md`、`openapi.yaml` 和 `asyncapi.yaml`，明确 HTTP、WebSocket、
  JSON 字段、数组编码、单位、坐标系、错误和版本边界。

## 1.8.1 - 2026-07-30

### 修复

- ZMQ 相机流新增 `frame_id` 与 `timestamp_ms` 陈旧 watchdog；收到消息但帧身份持续
  3 秒不递增时，清空该安装位旧缓存并重建 SUB socket，避免冻结帧长期伪装成最新帧。
- RGBD 与纯彩色稳定帧等待在超时窗口内只观察到零个或一个唯一帧时，明确报告
  “camera frame stream did not advance”，不再误报为普通画面不稳定。
- 持续收到彩色帧但没有深度载荷时，恢复流程改为对对应安装位执行深度关闭再开启，
  修复上游报告 `depth_enabled=true`、实际却持续发布 `depth_format=0` 时重复开启无效的问题。
- 深度开关复位时同步废弃旧内参并重新查询；控制端返回非有限数或非正 `fx/fy` 时
  不再缓存，而是进入退避重试，避免全零内参污染后续 RGBD 帧。
- 三球检测在反投影前显式校验内参，非法输入直接返回清晰的内参错误，不再因
  `inf/NaN` 三维坐标误报 `relative_geometry_mismatch`。
- 三球实机测试的状态、稳定帧和检测阶段各自使用独立 RPC 客户端，避免跨阶段
  复用异常 REQ 状态；客户端期望功能版本同步为 `1.8.1`。
- 公共 RPC 客户端改为每次调用使用独立 REQ socket，修复同一客户端连续执行
  短查询与稳定帧长等待时服务端已响应、客户端却持续等待直至超时的问题。

## 1.8.0 - 2026-07-29

### 变更

- ZMQ 相机运行时不再在服务启动线程中一次性初始化深度和内参；上游控制服务尚未
  就绪时，后台采集线程会持续按 `2-30 s` 指数退避重试，后续恢复无需重启
  CameraPipeline。
- 深度恢复以实际收到 RGBD 帧为准；连续 30 帧只有彩色载荷时自动重新请求开启
  深度，修复启动时序异常后长期停留在 RGB-only 状态的问题。
- CameraPipeline 对外的 RGB、Depth、RGBD ZMQ 转发分别由彩色缓存和 RGBD 缓存
  驱动；深度暂不可用时彩色订阅仍保持可用。

## 1.7.0 - 2026-07-29

### 变更

- ChArUco 请求增加 `enable_debug`，响应增加最终检测帧的 `overlay_bgr`；调用方可
  显示真正参与位姿求解的 marker、ChArUco 角点和坐标轴叠加结果。
- CameraPipeline 线协议升级到 10。

## 1.6.0 - 2026-07-29

### 变更

- 相机运行时分别维护彩色帧与 RGBD 帧缓存；上游瞬时无深度帧仍可进入彩色缓存。
- 稳定帧检测新增纯彩色入口，只检查时间连续性和 RGB 变化。
- ChArUco 检测改用纯彩色稳定帧，不再读取深度图或依赖深度稳定阈值；RGBD 算法
  继续使用原有 RGB+深度稳定检查。

## 1.5.3 - 2026-07-29

### 修复

- 根据头部相机最新静止流实测噪声，将深度相邻帧中位差阈值从 `8 mm` 调整为
  `18 mm`、75 分位差阈值从 `25 mm` 调整为 `45 mm`；RGB、有效深度比例、
  `1 s` 稳定时长和帧连续性约束保持不变。

## 1.5.2 - 2026-07-29

### 修复

- ZMQ RGBD 解码现在严格校验协议版本、消息总长度和深度尺寸；上游帧头明确表示
  `depth_format=0` 时丢弃该瞬时无深度帧，不再错误调用 LZ4 解压并重建流 socket，
  避免头部相机稳定窗口因无效重连持续中断。

## 1.5.1 - 2026-07-29

### 优化

- CameraPipeline RPC 客户端改为正常请求复用持久 REQ 连接，连续采集多帧时不再为
  每一帧重复创建 TCP/SSH 转发流；请求失败后仍会关闭失效 socket，并在下一次调用
  时自动重建连接。

## 1.5.0 - 2026-07-28

### 变更

- 三球首次先验检测不再维护黄、红、紫等固定 HSV 颜色表，改为仅根据请求中每个球的
  RGB HEX 颜色动态生成 HSV 宽范围；跨越 Hue 首尾的颜色统一自动拆分范围。
- 已记录先验仍优先使用调用方传入的每球专属 `hsv_ranges`，检测结果顺序继续严格
  跟随请求先验顺序。

## 1.4.2 - 2026-07-23

### 部署

- 根据实际重启时间线将 CameraPipeline systemd 进程启动、停止上限分别设为 20 秒
  和 15 秒；同步脚本允许最多 20 秒完成三路相机初始化，并以目标相机在线而非仅
  端口监听作为业务就绪条件。
- CameraPipeline 启停日志增加实际耗时，SSH/SCP 连接超时限制为 10 秒。
- 同步脚本在备份后删除两个遗留 CameraPipeline unit，并精确同步基于 systemd 的
  CameraPipeline、RecordReplay 重启脚本，避免手工进程与正式 unit 重复运行。

## 1.4.1 - 2026-07-23

### 修复

- 收紧首次三球检测的黄色与紫色参考 HSV 范围，避免低饱和木纹、铝型材反光和暗色
  设备与真实小球粘连或形成错误候选。
- 三阶段冒烟测试改为先保存 debug 原图、深度图和 overlay，再校验完整检出状态；
  检测失败时仍保留现场证据用于调参。

## 1.4.0 - 2026-07-23

### 变更

- `CameraStatusResponse` 增加远端 `service_version`，客户端暴露本地期望功能版本；
  三球冒烟测试在连通性阶段强制核对两端版本，线协议升级到 9。
- 三球冒烟测试改为连通性、无相对位置先验检测、真实相对位置先验复检三个阶段；
  后两阶段必须完整检出三球并保存末帧原图、深度图和 overlay。

## 1.3.1 - 2026-07-23

### 部署

- 新增本机一键同步与重启脚本，部署前后校验 `camera_pipeline/` 与
  `record_replay/` 的文件清单和 SHA-256，并统一通过 systemd 管理两个服务。
- 部署时停用现场遗留的 `orin-camera-pipeline.service`，避免两个 CameraPipeline
  unit 及手工启动进程争用 6200 端口。

## 1.3.0 - 2026-07-23

### 变更

- 以三球先验是否包含有效毫米尺度相对位置关系区分常规检测与先验采集；有球先验但
  无有效相对位置关系时必须启用 debug，否则服务明确拒绝请求。
- 空先验请求保持为独立的无目标冒烟路径，不会被误判为先验采集。
- 先验采集端对每个采样请求启用 debug，并强制保存 debug overlay 作为采集证据。

## 1.2.0 - 2026-07-23

### 变更

- 三球先验增加每球专属 `hsv_ranges`；首次记录使用参考色宽范围，后续检测优先使用
  30 帧标定得到的窄范围。
- 三球检测结果增加候选内部颜色像素的 `observed_hsv`，Hue 使用圆均值处理红色首尾
  环绕；线协议版本升级到 8。
- 先验记录改为收集 30 个不同且完整的帧，经中心与直径 MAD 异常剔除后使用保留帧
  均值，并在保留帧少于 24 时拒绝写入。

## 1.1.0 - 2026-07-23

### 变更

- 三球检测改为优先按模型球间相对距离联合选择候选，单球颜色与轮廓分数仅用于
  几何一致候选的次级排序。
- 增加物理直径和三球相对距离硬校验；偏差超过容差时返回明确未检出结果，不再输出
  仅由错误色块形成的球位置。
- 三球先验和检测结果的尺寸字段由 `radius_mm` 统一改为 `diameter_mm`，线协议版本
  升级到 7；首次先验采集没有球间位置先验时优先按物理直径选择候选。

## 1.0.1 - 2026-07-23

### 修复

- ChArUco 检测迁移到 `cv2.aruco.CharucoDetector.detectBoard()`，修复 Orin OpenCV
  4.13 不再导出 `interpolateCornersCharuco()` 导致服务请求失败的问题。
- DingTai Python 3.10/3.12 环境统一声明单一 `opencv-python==4.13.0.92`，避免多个
  OpenCV wheel 共同覆盖 `cv2` 命名空间。
- 新增可平铺部署到 Orin `test/` 根目录的 ChArUco 服务真实相机测试入口。

## 1.0.0 - 2026-07-21

### 初始基线

- 提供统一的多相机查询、RGBD/彩色/深度订阅和稳定帧 API。
- 提供三球检测与 Charuco 检测服务能力。
- 公共客户端同时支持 Windows 开发机访问 Orin 和 Orin 本机服务调用。
- 服务功能版本从 `1.0.0` 开始维护；网络协议版本独立管理。
