# Dingtai 四服务 Orin 部署指南

文档版本：`1.1.0`（2026-08-05）

本文用于在一台全新的 Orin 上部署当前四个常驻服务，并把网络、Python 环境、证书、systemd 和外部客户端入口配置到可验收状态：

- CameraPipeline：相机控制、检测、HTTP 和 WebSocket 帧流。
- RecordReplay：记录回放 HTTP 服务。
- RobotControl：机器人控制 HTTP 服务。
- API Gateway：外部客户端唯一的 HTTPS/WSS 入口。

本指南以 `C:\Projects\Dingtai` 为本机唯一源代码，以 Orin 用户 `wuji-brain` 和工作目录
`/home/wuji-brain/workspace` 为部署约定。不要只修改 Orin 上的代码副本，也不要把 Windows
xCoreSDK 二进制同步到 Orin。

## 1. 当前版本与网络目标

本指南当前采用 IPv4-only 业务拓扑：Orin 的 `eth0` 只承载固定 IPv4 业务地址，IPv6 在
NetworkManager 连接中禁用。Flutter、GUI 和其他外部客户端统一通过
`https://wujibrain-desktop:443` 访问 Gateway；不要把客户端 URL 改成 IPv4 或 IPv6 字面量。

### 1.1 服务版本

部署前以本机契约文件为准，当前版本为：

| 服务 | 当前版本 | Orin systemd 单元 | 正式外部入口 |
| --- | --- | --- | --- |
| CameraPipeline | `1.10.0`；CPW1 `10`；CPWS1 `1` | `camera-pipeline.service` | Gateway `/api/v1/camera/*`、`/api/v1/camera-ws/*` |
| RecordReplay | `1.11.0` | `record-replay.service` | Gateway `/api/v1/record-replay/*` |
| RobotControl | `0.6.0`；HTTP API `1` | `robot-control.service` | Gateway `/api/v1/robot-control/*` |
| API Gateway | `0.2.2` | `api-gateway.service` | `https://wujibrain-desktop:443` |

### 1.2 Orin 网卡和地址

`Wired connection 1` 必须先确认实际绑定的是 `eth0`，不要仅凭连接名称猜测：

```bash
nmcli -t -f NAME,DEVICE connection show --active
nmcli -f connection.id,connection.interface-name connection show "Wired connection 1"
ip -br addr show eth0
```

目标网络参数如下：

| 项目 | 值 |
| --- | --- |
| 物理网卡 | `eth0` |
| NetworkManager 连接 | `Wired connection 1` |
| IPv4 地址 | `192.168.100.70/24` |
| IPv4 网关 | `192.168.100.1` |
| IPv4 DNS 服务器 | `192.168.100.1`、`223.5.5.5` |
| IPv6 业务网络 | 禁用；`eth0` 不配置 ULA 或全局 IPv6 地址 |
| Gateway hostname | `wujibrain-desktop` |

当前不需要为 `fd3c:7b91:4e20:100::/64` 做 Orin 侧地址冲突探测；该前缀不属于本部署的
业务网络。若未来重新启用 IPv6，必须先由网络管理员确认前缀规划、网关、NDP/RA 和上游
路由，再单独更新 NetworkManager 配置、DNS 和验收步骤。

## 2. 配置 NetworkManager

先保存当前配置和路由，确认 SSH 仍通过 IPv4 可达。以下命令在 Orin 本机终端执行：

```bash
nmcli connection show "Wired connection 1" > ~/wired-connection-before.txt
ip -4 route show > ~/ipv4-route-before.txt
ip -6 route show > ~/ipv6-route-before.txt
```

先找到 `eth0` 对应的 NetworkManager 连接名。下面假设连接名为
`Wired connection 1`；如果输出不同，后续命令中的 `CONN` 必须替换为实际名称：

```bash
nmcli -t -f NAME,DEVICE connection show --active
CONN="Wired connection 1"
nmcli -f connection.id,connection.interface-name connection show "$CONN"
```

固定 IPv4，并禁用该连接的 IPv6：

```bash
sudo nmcli connection modify "$CONN" \
  ipv4.method manual \
  ipv4.addresses "192.168.100.70/24" \
  ipv4.gateway "192.168.100.1" \
  ipv4.dns "192.168.100.1 223.5.5.5" \
  ipv4.never-default no \
  ipv6.method disabled \
  connection.autoconnect yes
```

如果设备之前配置过本指南旧版本的 IPv6，`ipv6.method disabled` 后仍可能暂时残留运行时
地址或路由。仅当下列命令仍能看到旧的 `fd3c...` 条目时执行对应清理；不要用宽泛的
`ip -6 route flush dev eth0`，以免误删其他维护所需路由：

```bash
if ip -6 addr show dev eth0 | grep -q 'fd3c:7b91:4e20:100::70/64'; then
  sudo ip -6 addr del fd3c:7b91:4e20:100::70/64 dev eth0
fi
if ip -6 route show dev eth0 | grep -q '^fd3c:7b91:4e20:100::/64'; then
  sudo ip -6 route del fd3c:7b91:4e20:100::/64 dev eth0
fi
```

重新激活连接。该操作可能导致当前 SSH 短暂断开；应从 Orin 本地终端执行，或确认可以
通过 `192.168.100.70` 重新连接后再继续：

```bash
sudo nmcli connection up "$CONN"
nmcli -f connection.id,connection.interface-name,ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns,ipv6.method connection show "$CONN"
ip -br addr show eth0
ip -4 route
ip -6 addr show dev eth0
ip -6 route
```

预期结果：

```text
eth0    UP    192.168.100.70/24
192.168.100.0/24 dev eth0
default via 192.168.100.1 dev eth0
```

IPv4 通过设备路由器的无线中继访问外网需要 `192.168.100.1` 提供可达的默认路由和 DNS。
`ip -6 addr show dev eth0` 和 `ip -6 route` 不应再出现 `fd...` 或其他全局 IPv6 业务地址/路由；
系统可能仍显示 `fe80::/64` 链路本地地址。若仍出现业务 IPv6 条目，先检查连接是否确实为
`$CONN`、`ipv6.method` 是否为 `disabled`，再执行上面的条件清理步骤。

## 3. DNS、hostname 与证书

### 3.1 主机名

```bash
sudo hostnamectl set-hostname wujibrain-desktop
hostname
```

在局域网 DNS/路由器上配置精确的 A 记录：

```text
wujibrain-desktop  A     192.168.100.70
```

`ipv4.dns "192.168.100.1 223.5.5.5"` 只是指定 DNS 服务器，不会创建上述 A 记录。
当前 IPv4-only 拓扑不要发布指向旧 IPv6 地址的 AAAA 记录；如果 DNS 中仍有该 AAAA 记录，
应删除或在重新启用 IPv6 前保持停用。修改完成后从客户端验证：

```powershell
Resolve-DnsName wujibrain-desktop -Type A
```

### 3.2 CasiaHand CA 与 Gateway 证书

正式 GUI、Flutter Web 和其他客户端必须使用 `wujibrain-desktop` hostname，不得把 URL 改成
IPv4/IPv6 字面量。客户端必须安装并信任 `CasiaHand Root CA`，禁止使用 `-k`、`verify=False`
或关闭 TLS 校验绕过问题。

在全新 Orin 上先完成 hostname 和网络配置，再执行无参数证书注册脚本：

证书注册脚本来自本机仓库。全新设备首次部署时，先按第 5.1 节确认 SSH，再执行第 5.2
节中的“首次证书脚本准备”步骤，把 `api_gateway/certificates` 放到 Orin 工作目录；不要
在证书文件不存在时直接重启 Gateway。

```bash
bash /home/wuji-brain/workspace/api_gateway/certificates/scripts/register_api_gateway.sh
```

检查证书 hostname：

```bash
openssl x509 \
  -in /etc/dingtai/api-gateway/tls/api-gateway.fullchain.pem \
  -noout -subject -issuer -ext subjectAltName
```

证书文件应存在且可供 Gateway 读取：

```bash
test -r /etc/dingtai/api-gateway/tls/casiahand-root-ca.crt.pem
test -r /etc/dingtai/api-gateway/tls/api-gateway.fullchain.pem
test -r /etc/dingtai/api-gateway/tls/api-gateway.key.pem
```

Windows 客户端从仓库根目录安装 CA：

```powershell
pwsh -NoProfile -File .\api_gateway\certificates\scripts\install_casiahand_ca_windows.ps1
```

## 5. 源码同步与 systemd 部署

### 5.1 SSH 前置检查

本机 PowerShell 7 执行：

```powershell
ssh orin "hostname; id -un; test -d /home/wuji-brain/workspace"
```

必须确认 SSH 目标解析到当前 Orin 的 `192.168.100.70`，并且远端用户是 `wuji-brain`。部署
脚本需要远端 sudo 权限；sudo 密码只能保存在本机未提交的部署脚本配置中，不能写入本指南、
终端日志、Git 或远端服务文件。

### 5.2 四服务部署

首次部署还没有完整工作目录时，先从本机仓库根目录准备证书脚本：

```powershell
ssh orin "mkdir -p /home/wuji-brain/workspace/api_gateway/certificates/scripts"
scp .\api_gateway\certificates\scripts\register_api_gateway.sh orin:/home/wuji-brain/workspace/api_gateway/certificates/scripts/
scp .\api_gateway\certificates\scripts\create_casiahand_ca.sh orin:/home/wuji-brain/workspace/api_gateway/certificates/scripts/
scp .\api_gateway\certificates\scripts\issue_api_gateway_certificate.sh orin:/home/wuji-brain/workspace/api_gateway/certificates/scripts/
scp .\api_gateway\certificates\scripts\install_api_gateway_certificate.sh orin:/home/wuji-brain/workspace/api_gateway/certificates/scripts/
ssh orin "bash /home/wuji-brain/workspace/api_gateway/certificates/scripts/register_api_gateway.sh"
```

确认证书文件存在后，再执行四服务同步。后续更新不需要重复复制证书脚本；证书续期或重新
注册必须保持 hostname 规则，并在客户端重新信任对应 CA。

本机仓库根目录执行：

```powershell
pwsh -NoProfile -File .\scripts\sync_and_restart_services.ps1
```

该流程会：

1. 按本机源代码生成部署清单和 SHA-256。
2. 同步 CameraPipeline、RecordReplay、RobotControl、API Gateway 及所需源码。
3. 安装四个 systemd 单元并执行 `systemctl daemon-reload`。
4. 按服务依赖停止、替换、启动和就绪检查。
5. 通过 CameraPipeline 相机状态、RecordReplay `/status`、RobotControl `/api/v1/health` 和 Gateway `/api/v1/gateway/health` 完成只读验收。

维护窗口只需要部署单个服务时，使用：

```powershell
pwsh -NoProfile -File .\scripts\sync_and_restart_services.ps1 -ApiGatewayOnly
pwsh -NoProfile -File .\scripts\sync_and_restart_services.ps1 -RobotControlOnly
pwsh -NoProfile -File .\scripts\sync_and_restart_services.ps1 -RestartOnly -CameraPipelineOnly
```

涉及 CameraPipeline 公共协议或客户端时，必须将 CameraPipeline 与 RecordReplay 作为同一批次
部署。`RecordReplay` 可能涉及机械臂、AGV、夹爪、M11 或升降机构；部署前确认设备区域安全，
但不要把部署验收扩展成 `/start`、运动测试或控制 POST。

### 5.3 四个 systemd 单元和端口

| 服务 | 当前 systemd 启动参数 | 关键端口 |
| --- | --- | --- |
| CameraPipeline | `python -m camera_pipeline.service --bind-addr tcp://0.0.0.0:6200` | ZMQ `6200–6203`；HTTP `6400`；WebSocket `6401` |
| RecordReplay | `python -m record_replay.service --host 0.0.0.0 --port 6300` | HTTP `6300` |
| RobotControl | `python -m robot_control.service --host 127.0.0.1 --port 6500` | HTTP `6500`，仅 loopback |
| API Gateway | `python -m api_gateway.service --host 0.0.0.0 --port 443` | IPv4 `0.0.0.0:443` |

当前 `robot-control.service` 未显式声明 `User=`，因此按现有 unit 由 systemd 默认用户运行；
如后续要做权限收紧，必须单独确认 Linux SDK、qmlinker、设备节点和日志目录权限，不能在新机
部署时静默改动。

Gateway 内部固定通过 loopback 转发：

```text
CameraPipeline HTTP       127.0.0.1:6400
CameraPipeline WebSocket  127.0.0.1:6401
RecordReplay              127.0.0.1:6300
RobotControl              127.0.0.1:6500
```

Orin 本机服务间调用和诊断不要绕行 Gateway；正式 GUI/Flutter 客户端只能使用 Gateway 的
HTTPS/WSS 443 和公开 URL 前缀。

## 6. 防火墙与外部访问边界

IPv4-only 拓扑下，防火墙至少应允许 LAN 到 Gateway 的 TCP 443：

```bash
sudo iptables -I INPUT 1 -i eth0 -s 192.168.100.0/24 \
  -p tcp --dport 443 -m conntrack --ctstate NEW -j ACCEPT
```

如果启用默认拒绝策略，必须同时保留已建立连接、SSH 维护通道和必要的 ICMP；不要
在没有回滚方案时远程直接设置 `INPUT DROP`。CameraPipeline 的 `6200–6203`、`6400`、
`6401` 和 RecordReplay 的 `6300` 不应作为正式客户端入口暴露给 LAN；RobotControl 的
`6500` 已由 systemd 配置为 loopback。

iptables 规则必须按设备实际使用的持久化机制保存，例如已安装并启用
`netfilter-persistent` 时执行：

```bash
sudo netfilter-persistent save
sudo systemctl enable netfilter-persistent
```

保存后检查：

```bash
sudo iptables -S
```

## 7. 部署验收

### 7.1 网络

```bash
ip -4 addr show dev eth0
ip -4 route
ping -c 3 192.168.100.1
getent ahostsv4 wujibrain-desktop
```

IPv4 网关 ping 和 `getent ahostsv4` 必须成功。当前拓扑不验收 IPv6 网关或 IPv6 外网；如果
`ip -6 addr show dev eth0` 或 `ip -6 route` 仍显示 `fd...` 或全局业务地址/路由，说明 IPv6
尚未按指南完成禁用和清理。

### 7.2 四服务状态与监听

```bash
systemctl is-enabled camera-pipeline.service record-replay.service \
  robot-control.service api-gateway.service
systemctl is-active camera-pipeline.service record-replay.service \
  robot-control.service api-gateway.service
ss -ltn '( sport = :443 or sport = :6400 or sport = :6401 or sport = :6300 or sport = :6500 )'
```

当前 IPv4-only 业务入口至少必须出现：

```text
0.0.0.0:443
```

由于 API Gateway 代码支持双栈，`ss` 在部分 Linux 内核配置下仍可能显示 `[::]:443`；这不
代表 Orin 的 `eth0` 具备业务 IPv6 可达性。验收以 `eth0` 无业务 IPv6 地址、客户端 DNS
使用 A 记录以及 IPv4 TCP 443 可达为准。

### 7.3 只读健康检查

```bash
# CameraPipeline：直接访问 Orin 本机端口
curl -fsS http://127.0.0.1:6400/api/v1/health

# RecordReplay：只读状态，不调用 /start
curl -fsS http://127.0.0.1:6300/status

# RobotControl：只读契约健康检查，不调用 /status 或控制 POST
curl -fsS http://127.0.0.1:6500/api/v1/health

# Gateway：使用 hostname 和 CA，不使用 IP 字面量作为 URL 主机名
gateway_hostname="$(hostname)"
curl -fsS --cacert /etc/dingtai/api-gateway/tls/casiahand-root-ca.crt.pem \
  --resolve "${gateway_hostname}:443:127.0.0.1" \
  "https://${gateway_hostname}/api/v1/gateway/health"
```

外部客户端使用：

```text
https://wujibrain-desktop/api/v1/camera/health
https://wujibrain-desktop/api/v1/record-replay/status
https://wujibrain-desktop/api/v1/robot-control/health
wss://wujibrain-desktop/api/v1/camera-ws/cameras/head_camera/color
```

Flutter Web 调试来源必须保留在 Gateway CORS 允许范围内：`localhost`、`127.0.0.1` 和
`::1` 的 HTTP/HTTPS 来源，以及正式的 `https://wujibrain-desktop`。不要为了调试把 Gateway
改成任意 Origin 反射。

## 8. 故障排查顺序

1. `ssh orin` 超时：先检查本机到 `192.168.100.70:22`、IPv4 路由和 Orin SSH 服务。
2. IPv4 外网不通：检查 `192.168.100.1`、默认路由、DNS 和无线中继。
3. 出现 IPv6 地址：检查连接是否绑定到 `eth0`、`ipv6.method` 是否为 `disabled`，重新激活正确连接。
4. Gateway 只有 IPv4 监听：检查 `api_gateway/service/__main__.py` 和 `journalctl -u api-gateway.service`。
5. TLS 失败：检查 hostname、CA 信任、证书 SAN 和系统时间；不要改成 IP URL 或关闭校验。
6. Gateway health 正常但后端失败：直接检查对应 loopback 服务和日志，不要把 Orin 本机诊断改成 Gateway URL。
7. RecordReplay 失败：先确认依赖 CameraPipeline、先验文件和 CSV 已部署，只读检查 `/status`；禁止自动调用 `/start`。

常用日志命令：

```bash
journalctl -u camera-pipeline.service -n 100 --no-pager
journalctl -u record-replay.service -n 100 --no-pager
journalctl -u robot-control.service -n 100 --no-pager
journalctl -u api-gateway.service -n 100 --no-pager
```

本指南的部署验收不包含机器人、AGV、夹爪、升降、相机硬件动作或 RecordReplay 回放；这些
必须由现场人员在确认安全后手动执行。
